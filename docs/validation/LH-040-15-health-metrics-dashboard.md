# LH-040-15 匿名健康指标与管理看板验收记录

日期：2026-07-30  
范围：Desktop 运行标记、Cloud 模型代理、匿名小时聚合、Admin Web、PostgreSQL migrations 007—008、OpenAPI

## 结论

已建立近 24 小时运营健康看板。异常退出由 Desktop 本地严格运行标记在下一次启动时报告；聊天成功率
和上游延迟直接由 Cloud 模型代理在收到上游响应头时汇总；升级成功率复用客户端更新结果。后台只读取
无身份的小时聚合，不提供逐设备事件查询。

## 指标定义

| 指标 | 定义 |
|---|---|
| 异常退出率 | `previous_exit=unclean / (clean + unclean)`；首次运行没有分母 |
| 模型成功率 | 上游 2xx / 所有已到达上游的代理请求 |
| 模型延迟 | Cloud 发起请求到收到上游响应头的 TTFB 桶，不是完整流完成时间 |
| 升级成功率 | `healthy / (healthy + failed + rollback_completed)` |
| 错误摘要 | 固定公开产品错误码的计数与 Top 5 |
| 版本分布 | `client_started` 按 Desktop 版本计数 |

没有样本时比率返回 `null`，管理页面显示“—”，避免把“无数据”误报为 0%。

## 隐私与故障边界

- `client-run-marker.json` 只允许 schema 和 `running|clean`，不含时间、身份、路径或会话；原子写入并拒绝
  符号链接和非普通目标。读取或写入失败只记录固定错误码，不阻断客户端。
- `model_request_hourly` 只含 API 类型、固定结果、TTFB 桶和 count；不含设备/用户/租户、model ID、URL、
  请求/响应、Token 数、原始毫秒或错误文本。
- 模型指标存储失败只记录 `model.metrics_dropped`，不会改变或阻断模型响应。
- Admin 看板按近 24 小时读取聚合，不返回逐设备遥测。

## 自动化证据

- 共享契约接受 `previous_exit=clean|unclean`，拒绝原因、堆栈和未知字段。
- 运行标记覆盖首次运行、正常退出、未清理退出、损坏文件、符号链接和非普通文件。
- 模型网关覆盖 2xx、上游拒绝、超时以及指标存储失败不阻断。
- 看板聚合覆盖时间窗口、分母、空样本、延迟桶、版本和固定错误码，序列化结果不含身份或内容字段。
- PostgreSQL 条件测试覆盖退出事件和模型指标累加；未配置测试数据库时保持显式跳过。
