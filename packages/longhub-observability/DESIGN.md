# LongHub Observability 设计

## 威胁模型

日志可能被本地诊断包、集中采集平台、运维人员或备份系统长期读取。上游错误、子进程 stderr 和未来
新增字段可能意外夹带设备 Token、Gateway/Bridge Token、API Key、授权码或用户文件原文。

## 安全决策

- 所有结构化字段先执行键名分类和递归脱敏，再序列化；秘密字段和用户内容字段统一替换为
  `[REDACTED]`，不保留尾号或摘要。
- Error 只保留 `name/message/code`，不输出 stack；message 还要执行 Bearer、URL 参数、命令参数和
  已知凭据格式清理。Manager 还会动态登记本次启动的设备、Gateway、Bridge Token，对无标签子进程
  输出执行精确值替换。
- 元数据 `ts/level/component/event` 由 Logger 最后写入，业务字段不能覆盖。
- 默认 sink 使用 `console.log` 输出已经脱敏并完成大小限制的单行 JSON，这是容器标准输出接口，不是调试
  旁路；调用方注入的 sink 也只能收到同一规范化字符串。
- 深度、数组长度和字符串长度均有限制，循环引用输出固定标记。
- Cloud 审计数据在存储实现中再次调用 `redactLogValue()`，防止绕过控制台 Logger。

## 安全边界与已知风险

脱敏降低正常日志读取、收集和备份造成的泄露，不能抵御已经控制应用进程或同一用户会话的恶意程序。
任意自然语言秘密若没有敏感键名、格式或上下文标签，无法可靠自动识别；因此“禁止记录请求体、模型
消息、工具输入输出和用户文件内容”仍是首要规则，脱敏是纵深防御而不是记录原文的许可。

`client-telemetry.ts` 是端云共享的允许列表，不是宽泛事件 SDK：没有自由 `properties/labels/message`，
也没有设备、用户、租户、会话、Agent 或 Pack 标识字段。解析器检查精确键集合、固定枚举、语义版本、
事件数量和接收时间窗，并重建对象以丢弃输入引用。Cloud 仍需在认证后再次调用解析器，不能只相信
Manager 类型；Store 只能接收已折算的匿名小时聚合。

Manager 日志由宿主在共享脱敏之后写入有界轮转文件；本包不负责磁盘生命周期。遥测网络队列、Cloud
鉴权限流和数据库聚合也分别由 Manager/Cloud 实现，本包只冻结最小数据契约和粗粒度桶。

## 变更历史

### 2026-08-11 - 客户端版本字段迁移为 Manager

**变更内容**：遥测事件的公开字段从 `desktop_version` 替换为 `manager_version`，严格解析器、类型与测试
同步迁移。

**变更理由**：正式客户端路线已经切换为 LongHub Manager，且 clean launch 不需要旧设备兼容。

**影响范围**：`ClientTelemetryEvent`、批次精确键校验、规范对象重建、文档和契约测试。

**决策依据**：不提供旧字段别名；旧字段会同时触发未知字段和新字段缺失校验，防止双写和统计口径分裂。

### 2026-07-30 - 增加严格匿名客户端遥测契约

**变更内容**：新增四类固定事件、精确键解析、批次/时间/版本限制和启动耗时/Agent 数量桶函数。

**变更理由**：共享类型可以减少端云漂移，但只有运行时严格重解析才能拒绝恶意或旧客户端追加的身份、
聊天、路径、URL、异常和自由标签。

**影响范围**：LongHub Manager、LongHub Cloud API、OpenAPI、隐私回归与小时聚合存储。

**决策依据**：不提供任意扩展字段，从契约结构上限制未来调用方；服务端重建规范对象形成第二道边界。

### 2026-07-29 - 建立统一日志脱敏边界

**变更内容**：增加递归字段脱敏、自由文本清理、异常收敛、大小限制及自动化回归测试。

**变更理由**：Credential Manager 只保护静态凭据；若错误或业务内容进入日志，仍会形成新的泄露面。

**影响范围**：Cloud API、Cloud 审计、Manager、Executor、Worker 和后续诊断能力。

**决策依据**：统一出口配合审计落库二次清理，可以让新增调用方默认获得相同防护并集中维护规则。
